Introducción

El Compilador Pedidos es una herramienta diseñada para procesar un Lenguaje de Dominio Específico (DSL) enfocado en la gestión logística, inventario y control de pedidos de una empresa.

A diferencia de los lenguajes de propósito general (como Python o C++), este compilador interpreta instrucciones semánticas específicas del negocio, permitiendo automatizar flujos como la creación de pedidos, asignación de repartidores, verificación de stock y transiciones de estado (ej. Pendiente → Procesando → En Ruta → Entregado).

El propósito principal de este proyecto es demostrar la aplicación práctica de la teoría de autómatas y lenguajes formales en la construcción de un analizador estructurado en tres fases: Léxica, Sintáctica y Semántica.

Descripción del Lenguaje

¿Qué tipo de lenguaje es?

Es un lenguaje estructurado e imperativo diseñado para ser altamente legible por humanos, asemejándose a un pseudocódigo o a reglas de negocio redactadas en español.

Estructura de un Programa Válido

Un programa válido consiste en una secuencia de sentencias terminadas por punto y coma (;). Permite:

  • Declaración de variables/propiedades: Cliente: "Juan";
  • Acciones Compuestas: Crear Pedido: P1;, Asignar Repartidor Juan: P1;
  • Cambios de Estado: Confirmar P1;, Entregado P1;
  • Estructuras de Control: Condicionales Si ... Sino ... Fin
  • Comentarios: // Esto es un comentario

Ejemplo de Sintaxis

Cliente: "Empresa ABC";
Crear Pedido: Ped001;
Asignar Repartidor Carlos: Ped001;

Si Total: 1500.50;
    Confirmar Ped001;
Sino
    Pendiente Ped001;
Fin

Fase 1: Analizador Léxico

El analizador léxico es la primera fase del compilador. Su tarea es leer el código fuente carácter por carácter, ignorar espacios en blanco y comentarios, y agrupar los caracteres en unidades lógicas con significado llamadas tokens.

Categorías de Tokens Reconocidos

Palabras Reservadas (ej. Crear, Asignar, Pedido, Cliente, Si, Fin)
Identificadores (Nombres definidos por el usuario que empiezan con letras y pueden contener números)
Números (Enteros y Reales, ej. 10, 1500.50)
Cadenas de Texto (Texto encerrado entre comillas dobles "texto")
Símbolos (Operadores y delimitadores :, ;, (, ), $, %)

Manejo de Errores Léxicos

Si el analizador encuentra un carácter o secuencia que no pertenece al alfabeto del lenguaje, genera un Error Léxico, pero continúa el análisis para reportar la mayor cantidad de errores posible. Ejemplos de errores: un identificador que comienza con número (1Pedido) o una cadena sin cerrar ("Hola).

Cliente: "Maria Gomez";
Crear Pedido: P1;
1ErrorLexico;

Fase 2: Analizador Sintáctico

La segunda fase, el análisis sintáctico (o parser), toma la lista de tokens generada por el analizador léxico y valida si estos siguen una secuencia lógica permitida, comprobando si cumplen con las reglas matemáticas llamadas gramáticas libres de contexto.

Si la estructura es válida, el analizador construye un Árbol de Sintaxis Abstracta (AST) que representa la jerarquía lógica de las instrucciones. Si encuentra una secuencia no válida, genera un Error Sintáctico y emplea una estrategia de recuperación (avanzar hasta encontrar un punto y coma ;) para continuar analizando.

Reglas Gramaticales Principales

PROGRAMA → LISTA_SENTENCIAS
LISTA_SENTENCIAS → SENTENCIA ; LISTA_SENTENCIAS | ε
SENTENCIA → DECLARACION_BASICA 
            | ACCION_COMPUESTA 
            | ACCION_ESTADO 
            | ESTRUCTURA_CONDICIONAL
DECLARACION → PALABRA_CLAVE : VALOR
ACCION_COMPUESTA → Crear Pedido : ID
ESTADO → Confirmar ID | EnRuta ID ...
CONDICIONAL → Si COND ; LISTA_SENT Fin

Ejemplos de Sintaxis

✔ Código Válido

Crear Pedido: P1;

✖ Código Inválido (Falta punto y coma)

Crear Pedido: P1

✖ Código Inválido (Orden incorrecto)

Pedido Crear: P1;

Fase 3: Analizador Semántico

La tercera fase, el análisis semántico, se encarga de revisar la coherencia lógica del programa. Aunque una instrucción esté correctamente escrita (sintaxis válida), podría no tener sentido en el contexto del negocio. Este analizador usa una Tabla de Símbolos para rastrear y validar el estado de cada entidad a medida que lee el código.

Reglas Lógicas Validadas

  • Verificación de Existencia: No se puede asignar un repartidor, ni usar una condición, ni cambiar el estado a un Pedido que no ha sido creado o registrado previamente.
  • Compatibilidad de Tipos: Campos como Cantidad, Precio, Impuesto o Total requieren estrictamente un valor numérico (entero o real). Campos como Cliente o Direccion requieren texto o identificadores.
  • Unicidad: No se puede crear un Pedido con un identificador que ya existe en la Tabla de Símbolos, evitando duplicidades.
  • Transiciones de Estado: Implementa una máquina de estados finitos implícita para los pedidos. Por ejemplo, un pedido no puede pasar a estado Entregado si primero no está EnRuta o no puede Facturarse si ha sido Cancelado, garantizando el flujo logístico real de la empresa.

Tipos de Errores Semánticos (SEM)

El analizador reporta códigos de error específicos para facilitar la depuración:

  • SEM-01 Pedido no creado: Intento de referenciar un pedido inexistente.
  • SEM-02 Pedido repetido: Intento de crear un pedido con un ID ya en uso.
  • SEM-03 Tipo de dato incorrecto: Ej. asignar texto a un campo numérico.
  • SEM-04 Entidad no registrada: Asignar un recurso (Repartidor/Empleado) que no existe.
  • SEM-05 Identificador inválido: Uso de un identificador no definido en contextos fuera de pedidos.
  • SEM-06 Secuencia de estado incorrecta: Transición logística no permitida en la máquina de estados.

Ejemplos de Lógica y Transiciones

✔ Flujo Logístico Válido

Crear Pedido: P100;
Confirmar P100;
Procesando P100;
EnRuta P100;

✖ Flujo Logístico Inválido (SEM-06)

Crear Pedido: P200;
// Error: P200 no puede pasar de Creado a Entregado
Entregado P200;

✖ Incompatibilidad de Tipos (SEM-03)

// Error: 'Cantidad' espera un valor numérico
Cantidad: "Veinte";

✖ Variable no declarada (SEM-01)

// Error: El pedido 'P_Null' no ha sido creado
Asignar Repartidor Juan: P_Null;

Fase 4: Tabla de Símbolos

La Tabla de Símbolos es una estructura de datos central en el compilador. Su función es almacenar y administrar la información de los identificadores (como pedidos, variables y entidades) a medida que son descubiertos durante el análisis del código fuente.

Esta tabla permite al analizador semántico tener "memoria" del estado del programa, asegurando que las reglas del negocio se apliquen a entidades concretas y permitiendo a las demás fases saber qué variables ya existen.

¿Qué información almacena?

Por cada identificador único en el código, la tabla registra un objeto (clase Simbolo) con los siguientes atributos:

  • Identificador: El nombre único de la variable o entidad (ej. P100, Juan, Total).
  • Clase: El rol que cumple dentro del contexto del negocio (ej. Pedido, Dato, Cliente).
  • Tipo de Dato: El tipo del valor subyacente (ej. IDENTIFICADOR, NUMERO, NUMERO_REAL).
  • Valor: El dato en bruto asignado a la variable (ej. 1500.5, P100).
  • Estado: Mantiene el flujo de vida de la entidad. Para los pedidos, registra su estado logístico (ej. Creado, Confirmado, EnRuta).
  • Línea: La línea del código fuente donde el símbolo fue declarado o modificado por última vez.

Código de Entrada (Ejemplo)

Cliente: "Maria Gomez";
Total: 1500.50;
Crear Pedido: P1;
Confirmar P1;

Fase 5: Resultado Final y Entorno de Análisis

A diferencia de un compilador tradicional que genera un archivo ejecutable binario (como un .exe o un bytecode), el Compilador Pedidos funciona como un motor de análisis estático integrado dentro de un Entorno de Desarrollo (IDE) especializado.

El resultado final del compilador no es un nuevo archivo traducido, sino una evaluación estructurada y un reporte interactivo en tiempo real sobre el flujo de las reglas del negocio.

Salidas que produce el Compilador

  • Análisis en Vivo: El compilador evalúa el código mientras se escribe, proporcionando resaltado de sintaxis y subrayando los errores directamente en el código fuente.
  • Reporte Tabular de Fases: Genera matrices detalladas y accesibles que comprueban matemática y lógicamente el código (Tokens, Tabla de Errores, etc.).
  • Renderizado de Árbol Sintáctico: Produce una representación interactiva del flujo lógico, que puede ser visualizada gráficamente o exportada a un archivo .html independiente.
  • Memoria de Ejecución Simulada: La salida definitiva para el usuario de la empresa es la Tabla de Símbolos, donde se presenta el estado logístico real, actualizado y validado de todos los pedidos, indicando si los flujos fueron consistentes.

El IDE del Compilador

La culminación técnica del proyecto es la interfaz gráfica construida en PyQt6, la cual centraliza todas las fases.

  • Editor Inteligente: Sistema de numeración de líneas, zoom adaptativo, atajos de teclado y sistema de diagnósticos con subrayados de colores para alertar de errores por fase.
  • Panel de Monitor: Un widget inferior multicapa que actúa como la consola de salida oficial, categorizando los resultados y facilitando la labor técnica de depurar las instrucciones de logística.

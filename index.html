Introducción

El Compilador Gestor de Pedidos es una herramienta diseñada para procesar un lenguaje específico orientado a la administración de pedidos, clientes, inventario, repartidores y estados de entrega.

A diferencia de un lenguaje de programación general, este compilador interpreta instrucciones propias de un negocio. Por ejemplo: crear pedidos, asignar repartidores, validar stock, confirmar entregas y verificar que el flujo logístico tenga sentido.

El proyecto demuestra cómo se aplican las fases principales de un compilador: análisis léxico, sintáctico y semántico, integradas en un entorno pensado como un sistema real de gestión.

Descripción del Lenguaje

¿Qué tipo de lenguaje es?

Es un lenguaje estructurado e imperativo diseñado para ser legible por usuarios técnicos y no técnicos. Su sintaxis se parece a reglas de negocio escritas en español.

Estructura de un programa válido

Un programa válido contiene instrucciones terminadas por punto y coma ;. Permite:

  • Registro de datos: Cliente: "Juan";
  • Creación de pedidos: Crear Pedido: P1;
  • Asignación logística: Asignar Repartidor Carlos: P1;
  • Estados: Confirmar P1;, EnRuta P1;
  • Condiciones: Si ... Sino ... Fin
  • Comentarios: // comentario

Ejemplo de sintaxis

Cliente: "Empresa ABC";
Crear Pedido: Ped001;
Asignar Repartidor Carlos: Ped001;

Si Total: 1500.50;
    Confirmar Ped001;
Sino
    Pendiente Ped001;
Fin

Fase 1: Analizador Léxico

El analizador léxico lee el código fuente carácter por carácter, ignora espacios y comentarios, y agrupa los caracteres en unidades llamadas tokens.

Categorías de tokens reconocidos

🔵 Palabras Reservadas 🟢 Identificadores 🟠 Números 🟩 Cadenas ⚙️ Símbolos

Manejo de errores léxicos

Si el analizador encuentra un carácter o secuencia que no pertenece al lenguaje, genera un Error Léxico. Por ejemplo: un identificador que empieza con número o una cadena de texto sin cerrar.

Código de entrada

// Registro de una orden
Cliente: "Maria Gomez";
Crear Pedido: P1;
1ErrorLexico;

Fase 2: Analizador Sintáctico

El analizador sintáctico toma la lista de tokens y revisa si siguen una estructura válida según la gramática del lenguaje.

Si la instrucción está bien formada, el compilador puede construir un Árbol de Sintaxis Abstracta. Si no, genera un error sintáctico.

Reglas principales

PROGRAMA → LISTA_SENTENCIAS
LISTA_SENTENCIAS → SENTENCIA ; LISTA_SENTENCIAS | ε
SENTENCIA → DECLARACION
            | ACCION_COMPUESTA
            | ACCION_ESTADO
            | CONDICIONAL

DECLARACION → PALABRA_CLAVE : VALOR
ACCION_COMPUESTA → Crear Pedido : ID
ESTADO → Confirmar ID | EnRuta ID | Entregado ID
CONDICIONAL → Si COND ; LISTA_SENT Fin

Fase 3: Analizador Semántico

El análisis semántico revisa que las instrucciones tengan sentido dentro del sistema de pedidos. Aunque una instrucción esté bien escrita, podría ser inválida si rompe la lógica del negocio.

Reglas lógicas validadas

  • Existencia: no se puede modificar un pedido que no fue creado.
  • Tipos de dato: cantidad, precio y total deben ser numéricos.
  • Unicidad: no se puede crear dos veces el mismo pedido.
  • Estados: un pedido debe seguir un flujo lógico.
  • Recursos: repartidores o entidades deben estar registradas.

Errores semánticos

  • SEM-01 Pedido no creado
  • SEM-02 Pedido repetido
  • SEM-03 Tipo de dato incorrecto
  • SEM-04 Entidad no registrada
  • SEM-05 Identificador inválido
  • SEM-06 Estado incorrecto

Ejemplos de lógica

✔ Flujo válido

Crear Pedido: P100;
Confirmar P100;
Procesando P100;
EnRuta P100;

✖ Flujo inválido

Crear Pedido: P200;
// Error: no puede pasar directo a Entregado
Entregado P200;

✖ Tipo incorrecto

// Cantidad espera un número
Cantidad: "Veinte";

✖ Pedido no creado

// Error: P_Null no existe
Asignar Repartidor Juan: P_Null;

Fase 4: Tabla de Símbolos

La tabla de símbolos almacena la información importante de los identificadores encontrados durante el análisis. Funciona como la memoria del compilador.

Información que almacena

  • Identificador: nombre del pedido o dato.
  • Clase: pedido, cliente, dato o recurso.
  • Tipo: identificador, número, cadena, etc.
  • Valor: contenido asignado.
  • Estado: estado logístico del pedido.
  • Línea: posición dentro del código fuente.

Código de entrada

Cliente: "Maria Gomez";
Total: 1500.50;
Crear Pedido: P1;
Confirmar P1;

Fase 5: Resultado Final

El resultado final no es un archivo ejecutable tradicional, sino un entorno de análisis que funciona como un panel para validar reglas de negocio dentro de un sistema gestor de pedidos.

Salidas que produce

  • Tokens: clasificación del código fuente.
  • Errores: léxicos, sintácticos y semánticos.
  • Tabla de símbolos: memoria del sistema.
  • Estados: seguimiento del pedido.
  • Reporte visual: resultados organizados en tablas.

IDE del Compilador

La interfaz puede integrarse en un entorno tipo dashboard, donde el usuario escribe instrucciones, ejecuta el análisis y revisa el estado de los pedidos.
